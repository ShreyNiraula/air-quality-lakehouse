# Check 0.7: city candidates

Run on 6 October 2026 (UTC). The script's unedited output is in `generated/0.7-city-candidates.md`. This page says how to read it and what stands out. Choosing the two cities is the owner's step (Owner B).

## How to read the table

- **A pair** is one reference monitor and one openSenseMap box within 1 km of each other. `plan.md` uses a city only if it has at least three pairs. One box near two monitors counts as two pairs, so the table also gives the number of different boxes and of different monitors.
- **Who is counted.** A monitor counts if OpenAQ lists it as a fixed reference monitor with a PM2.5 sensor, first reporting before 1 January 2025 and last reporting within 30 days of the run. A box counts if it says `outdoor`, has a sensor that the rule from check 0.5b places as PM2.5, was created before 1 January 2025 and last measured within 30 days of the run.
- **A city** is a group of monitors within 20 km of one another, named by the locality OpenAQ gives most often in the group. Where OpenAQ gives no locality, or gives a network's name, the label is a station or network name.
- **Sample days.** For the cities with at least three pairs, the script asks each archive whether it holds a file for the monitor or the box on the first day of each quarter, seven days in all. A box that was offline for long stretches shows up here.

## What stands out

- **55 cities have at least one pair, and 6 have at least three:** Antwerpen, Bucuresti, Berlin, Darmstadt, Marburg and Wien.
- **Berlin** has 4 pairs from 4 different boxes and 3 monitors. Every monitor and every box has a file on all 7 sample days.
- **Bucuresti** has 5 pairs from 4 boxes and 4 monitors. One box, `SENZOR-PM-BUCURESTI-6`, has a file on only 2 of the 7 days. Without it 4 pairs remain, from 3 boxes.
- **Wien** has 3 pairs, each with its own monitor and its own box. One box has a file on 6 of the 7 days.
- **Darmstadt** has 3 pairs, from only 2 boxes and 2 monitors. One box has a file on 6 of the 7 days.
- **Marburg** has 3 pairs from 2 boxes and 2 monitors. One box, `Marbacher Weg`, has a file on only 2 of the 7 days. Without it 2 pairs remain, which is below the rule.
- **Antwerpen** has 5 pairs, all with the same single box. Monitor 3313496 has no file on any sample day and carries the same name as monitor 3313497.
- **No monitor in any pair measures temperature or humidity.** The column says `neither` for all 55 cities. `plan.md` already takes the condition value for every pair from Open-Meteo weather at the monitor's location, and uses the box's own humidity as a second view, so this changes nothing in the plan.

## What this does not show

- **The 70% rule.** `plan.md` compares a pair only if the two share at least 70% of hours. That needs the readings themselves, so it is checked once a city's data is loaded. Seven sample days are only a first filter.
- **What is inside a monitor's file.** The script checks that a day's file exists for the monitor, not that it holds PM2.5 rows.
- **Boxes the name rule misses.** Check 0.5b showed the rule misses some PM2.5 sensors with unusual names, so a city may have a few more boxes than listed here.
