Read on 5 October 2026. The measured findings are in `generated/0.5-sensor-community.md`, the unedited output of `uv run python -m airquality.checks.sensor_community`, and in `generated/0.5-sensor-community-2025-06-01.md`, the same with `--date 2025-06-01`. ## Licence: named, but its conditions are not fully clear, so the source is dropped

**What Sensor.Community states.** The footer of <https://sensor.community/en/>, under "legal", links "DB Contents License" to <https://opendatacommons.org/licenses/dbcl/1-0/>, the Database Contents License (DbCL) v1.0. The script reads that link.

**Where nothing is stated.** The archive listing and the CSV files carry no licence text. The "Privacy & Terms" page (<https://sensor.community/en/privacy-terms/>, last modified 20.02.2020) is an imprint and a privacy policy and does not mention the data.

**What DbCL v1.0 says**, quoted from the licence page:
- 2.1: "The Licensor grants to You a worldwide, royalty-free, non-exclusive, perpetual, irrevocable copyright license to do any act that is restricted by copyright over anything within the Contents [...] These rights explicitly include commercial use [...] the right to sublicense the work."
- 2.2: "You must comply with the ODbL."
- 2.3: "This license does not cover any Database Rights, Database copyright, or contract over the Contents as part of the Database. Please see the ODbL covering the Database".

**What the Open Database License (ODbL) v1.0 asks**, quoted from <https://opendatacommons.org/licenses/odbl/1-0/>, because DbCL 2.2 makes it a condition:
- 4.3: "if you Publicly Use a Produced Work, You must include a notice associated with the Produced Work reasonably calculated to make any Person that uses, views, accesses, interacts with, or is otherwise exposed to the Produced Work aware that Content was obtained from the Database [...] and that it is available under this License."
- 4.4: "Any Derivative Database that You Publicly Use must be only under the terms of: i. This License; ii. A later version of this License similar in spirit to this License; or iii. A compatible license."

| Permission (for the source manifest) | Reading |
|---|---|
| Redistribution, modification, commercial use | Allowed for the readings by DbCL 2.1 |
| Attribution | Required: DbCL 2.2 makes ODbL a condition, and ODbL 4.3 asks for a notice on anything published from the data. The map at <https://maps.sensor.community/> credits "Measurements by Sensor.Community contributors" |
| Share-alike | Required for a published derived database, by ODbL 4.4 through DbCL 2.2 |

**What is unclear.** Sensor.Community names DbCL only. It does not itself name ODbL for the database, and it gives no wording for the credit. The table is the cautious reading of the two licence texts, not a statement by Sensor.Community.

**Decision: the source is dropped.** `plan.md` says a source whose licence is missing or unclear is dropped. The options were to accept the reading in the table, to ask Sensor.Community to confirm it, or to drop the source. On 5 October 2026 the owner chose to drop Sensor.Community and look for another low-cost source. The rest of this page is kept as the record of what was found.

## Which column is PM2.5

The dust file has `P1` and `P2`. The project's API page (<https://github.com/opendata-stuttgart/meta/wiki/EN-APIs>) lists "value_types: P1 (PM10), P2 (PM2.5)" for the PMS sensors and shows the SDS011 sending the same two value types. In the dust file read by the script, `P2` is never above `P1`, which fits `P2` being the finer fraction.

## Time

Timestamps carry no UTC offset. The same API page says the server sets the timestamp, and the script finds the newest live reading two minutes behind the current UTC time, so the timestamps are UTC. That page also says the archive is exported "once a day (around 8:00 am)"; the listing shows each day's folder complete about four hours after the UTC day ends.

## Days before 2026 are stored compressed

Inside a year folder the files are gzip-compressed and end in `.csv.gz`; the 2026 days at the top level are plain `.csv`. `plan.md` names the two folder forms but not the compression. The run on 1 June 2025 reads the compressed form.

## Value ranges

On 4 October 2026 every sampled reading is inside the proposed ranges. On 1 June 2025, 512 of 11,735 temperature readings are outside, in 2 of the 20 files, and the lowest is -146.1 °C, which is below any air temperature recorded on Earth. The script marks that run as differing so that such values get looked at. They are faulty readings of the kind the range exists to mark invalid, so this supports keeping -60 to 60. Humidity had no reading outside 0 to 100 on either day.
