# Check 0.4: OpenAQ day file

Run on 5 October 2026 at 05:19 UTC against location 2178, on its file for 21 September 2026. Nothing differs from what `plan.md` expects.

## What this check is for

`src/airquality/checks/openaq_file.py` is a one-off check that is run by hand. It is not the daily pull and not part of the pipeline, and nothing schedules it.

`plan.md` describes OpenAQ's files from the documentation: the field names, the unit text, which end of the hour a timestamp names, and how late a day's file arrives. Part 2 lists "On real files … the header, the exact unit string and the hour convention match what the contract says" and "The archive lag measured per source" among the checks to run before building, because the facts table still marked the contents of 2026 files as unverified. This script downloads one real file and prints each of those facts next to what the plan expects, so a wrong assumption shows up now and not after the pipeline is built on it.

The findings are what the OpenAQ source contract (task 1.1) will be written from, which is why the roadmap makes that task wait for this one. The daily pull itself comes later: the OpenAQ adapter (1.7), the backfill (1.9) and Airflow's daily run (1.10).

It is worth running again if OpenAQ changes its files, or for another station:

```
uv run python -m airquality.checks.openaq_file --location <id> --timezone <IANA name>
```

`tests/test_openaq_file_check.py` tests the comparison logic on made-up input. The tests never use the network.
